Rounds 2 & 3 · DAX

Filter context, made visible

A DAX measure never has one answer. It answers for whatever filters surround it. Change the slicers and watch the measures recalculate. The figures are example data, in thousands.









Measure
Calculates at query time
Uses the current filter context, takes no storage per row, and is the right home for totals, ratios and KPIs.


Calculated column
Calculates at refresh
Computed once per row and stored. Use it for a label or a bucket you need on an axis or slicer.


Date table
Required for time
One row per day with no gaps, marked as a date table. Time intelligence functions depend on it.




Cookbook
Copy these into New measure. Rename the tables and columns to match your model.













Round 4 · Data modelling


Star schema or snowflake


Put numbers you add up in one fact table and descriptions you slice by in dimension tables. Click a table for details, then switch to the snowflake to see how dimensions split further.












Grain first
Decide what one fact row means, for example one product on one order line. Every other choice follows from that.


One to many, one direction
Relationships run from a dimension (one) to the fact (many), and filters flow the same way. Avoid bidirectional filters unless you can explain why.


Keep facts narrow
Keys and numbers only. Move names, categories and flags into dimensions so the model stays small and fast.











Round 5 · Lakehouse


From raw files to a Power BI model


A lakehouse keeps open files in a data lake and adds warehouse features such as tables and transactions on top. Click each stage to follow one example dataset through it.










Delta
Open table format
Parquet files plus a transaction log. It gives ACID updates, schema enforcement and time travel on cheap lake storage.


OneLake
One lake per organisation
Microsoft Fabric stores every lakehouse and warehouse in a single logical lake, so teams share one copy of the data.


Direct Lake
Import speed, no copy
A Fabric storage mode where the semantic model reads Delta tables from OneLake directly instead of refreshing an imported copy.

Already a lakehouse thinker?
Databricks and Snowflake solve the same storage and compute problems as Fabric. The medallion pattern (bronze, silver, gold) and the star schema in the gold layer carry across unchanged.


Your transfer checklist
Can you state the grain? Do you have a Date dimension? Are measures defined once and reused? Can you explain how filters flow? If yes, you can pick up a new BI tool in weeks.











Round 6 · Sharing with stakeholders


Getting a Power BI report in front of people


A .pbix file cannot be converted into a standalone HTML page, because the visuals need the Power BI service to query the model. You publish the report, then choose how people reach it.






Internal
Workspace and app
Publish to a workspace, then bundle pages into an app. Viewers sign in, and access follows their licence and permissions.
Best for company stakeholders


Internal
Secure embed
In the service use File, Embed report, then the secure embed code. Place the iframe in an intranet page or SharePoint. Viewers still sign in.
Best for intranet pages


Public
Publish to web
Creates a public link and iframe anyone on the internet can open. No sign-in and no security. Many organisations disable it.
Only for data you would post publicly


Static
PDF or PowerPoint export
Export a snapshot for a meeting pack. Quick and offline, but not interactive and out of date as soon as the data changes.
Best for one-off reports


Developers
Power BI Embedded
Embeds reports in your own application with your own authentication, so customers do not need Power BI licences.
Best for customer-facing apps


Portfolio
Screenshot walkthrough
For a public portfolio, publish a report built on open sample data, and add annotated screenshots on a static page so recruiters see it even if the embed is blocked.
Best for your GitHub Pages site
